## 2.2 Dependency direction (who imports whom)

```
abrsim  ←── baselines  ←── evaluate.py ──→ agents (lazily, only if --agent)
   ↑                            ↑              │
   └──────────── agents ────────┴── train.py ──┘
plots → abrsim (to load traces) + CSVs in results/ and runs/
```

- `abrsim` depends on nothing but NumPy. It is the "environment package".
- `baselines` depends only on `abrsim`. They never need torch.
- `agents` depends on `abrsim`, plus `baselines.base.Policy` so the RL agent plugs into the same evaluation code.
- `evaluate.py` imports `agents` **lazily**, so running baselines does not require PyTorch.

## 2.3 The single most important interface

Every decision-maker implements `baselines.base.Policy`:

```python
class Policy:
    name = "policy"
    def reset(self): ...                    # start of every video
    def select(self, state, env) -> int:    # return a bitrate index 0..5
```

`state` is the same 6×8 observation the RL agent gets. `env` is read-only context: the manifest (chunk
sizes), the last action, the QoE parameters. MPC and the oracle need it; a real player knows these
things too. RB, BB, BOLA and the RL agent use only `state`.

Because all algorithms share this interface, `evaluate.run_policy(policy, env, n_traces)` treats the RL
agent and the baselines identically. That is what makes the comparison fair.

## 2.4 End-to-end data flow

```
tools/prepare_traces.py ──► data/traces/**, data/video/envivio/
tools/make_scenarios.py ──► data/traces/scenarios/

TRAINING
train.py
  load_dataset("train") ─► split 90/10 ─► RolloutCollector(16 × ABREnv, random start, noise)
  loop 30k:  collect 16 videos (48×16 transitions) ─► A2CAgent.update() (GAE, actor+critic step)
             every 250: validate greedy policy on the 10 % ─► best.pt
             every 1000: ckpt_XXXXXX.pt
  ─► runs/a2c_lin/{config.json, log.csv, best.pt, final.pt, ckpt_*.pt}

EVALUATION
evaluate.py --oracle --agent A2C=runs/a2c_lin/best.pt --traces hsdpa/test
  for each policy: ABREnv(noise off, start at trace beginning) ─► run_policy
  ─► results/baselines/hsdpa_test_lin/{<policy>.csv, <policy>_traces.csv, summary.csv} + printed table

FIGURES
plots/make_figures.py ─► reads results/ + runs/ ─► plots/figures/*.png|pdf
```

## 2.5 Output files explained

| File | One row per | Columns |
|---|---|---|
| `results/.../<policy>.csv` | chunk | trace, chunk, wall_time_s, trace_time_s, bitrate_kbps, buffer_s, rebuffer_s, delay_s, sleep_s, throughput_mbps, chunk_size, reward, quality, rebuffer_penalty, smooth_penalty, data_penalty |
| `results/.../<policy>_traces.csv` | trace | trace, qoe, bitrate_mbps, rebuffer_s, rebuffer_ratio, switches, startup_s, total_qoe |
| `results/.../summary.csv` | policy | mean and std of every per-trace metric |
| `runs/<name>/log.csv` | validation (every 250 iterations) | iter, time_s, train_reward, val_qoe, val_bitrate_mbps, val_rebuffer_s, val_switches, policy_loss, critic_loss, entropy, entropy_weight |
| `runs/<name>/*.pt` | checkpoint | actor and critic weights, both optimiser states, config, iteration, meta |
